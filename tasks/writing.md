# Task: Write RO/DRO Research Papers in OR/MS Style

Writing must reflect what has actually been proved. Do not use prose to upgrade an unaudited result.

## Introduction logic

A strong methods introduction usually follows: operational failure -> why the existing uncertainty model fails -> missing modeling primitive -> mathematical challenge created by it -> proposed framework -> theoretical/statistical/computational resolutions -> experimental/application evidence.

Avoid a long RO/DRO taxonomy unless it directly establishes the gap.

## Contribution bullets

Each contribution should pair an object with a result. Only use “exact,” “finite-sample,” “optimal,” or “first” after the corresponding audit/search passes.

## Literature positioning

Organize around the closest mathematical distinctions: uncertainty object, ambiguity-set construction, contextual information, decision dependence, recourse/information structure, finite-sample guarantee, and reformulation/algorithm.

## Theorem exposition

Before a theorem, state why it is needed, explain the main obstruction, and define new objects. After it, interpret what changed, state limitations/conditions, and separate mathematical consequences from managerial implications.

## Statistical language

Use exact labels: confidence/coverage, finite-sample out-of-sample bound, consistency, asymptotic optimality, regret/excess risk. Do not call an asymptotic approximation finite-sample evidence.

## Reviewer-proof wording

If a result contains oracle constants, say so. If a reformulation is a safe approximation, say so. Precision usually strengthens a theory paper.
